# AuthentiFace

Face recognition with anti-spoofing (presentation attack detection).

- **Recognition:** InsightFace `buffalo_l`. SCRFD detects the face and the ArcFace model (`w600k_r50`) produces a 512-d embedding.
- **Anti-spoofing (two selectable models):**
  - `old`: MiniFASNetV2 + MiniFASNetV1SE ensemble (80x80 input, PyTorch) from [Silent-Face-Anti-Spoofing](https://github.com/minivision-ai/Silent-Face-Anti-Spoofing).
  - `new`: MiniFASNetV2-SE, INT8 ONNX (128x128 input) from [facenox/face-antispoof-onnx](https://github.com/facenox/face-antispoof-onnx).
- **Matching:** N:1. One probe embedding is compared against all enrolled embeddings with a single cosine-similarity matrix product.
- **Pipeline order:** detect face, then spoof check, then recognition (only if live). Spoofed faces never reach identity matching.

The project aims to demonstrate the system and to find the conditions under which MiniFASNet-type models fail.

## Project structure

```
authentiface/
├── config.py               # thresholds, paths, model settings
├── enroll.py               # enroll people into the JSON database
├── test_images.py          # run the pipeline on images or folders (--model old|new)
├── demo_webcam.py          # live webcam demo (--model old|new, --cam N)
├── check_antispoof.py      # compare both models' P(real) on a folder of images
├── explain_antispoof.py    # occlusion maps + FFT view of what the models rely on
├── scripts/
│   └── download_models.py  # downloads both anti-spoof models
├── src/
│   ├── face_engine.py      # InsightFace detection + ArcFace embedding
│   ├── antispoof.py        # OldAntiSpoof, NewAntiSpoof, load_antispoof()
│   ├── minifasnet_arch.py  # old model network definition (downloaded)
│   ├── database.py         # JSON embedding store
│   ├── matcher.py          # N:1 cosine matching
│   ├── pipeline.py         # detect -> spoof check -> recognize
│   └── viz.py              # box and label drawing
├── models/antispoof/       # .pth and .onnx weights (not in repo)
├── db/embeddings.json      # generated by enroll.py (not in repo)
├── data/enroll/<person>/   # enrollment photos (not in repo)
├── data/test/              # test and spoof photos (not in repo)
└── outputs/                # annotated results (not in repo)
```

## Requirements

- Python 3.11.9
- Windows, Linux or macOS. CPU is enough; no GPU needed.
- On Windows, `insightface` may need the Microsoft C++ Build Tools ("Desktop development with C++" workload).
- Internet access on first run (about 280 MB for InsightFace models).

## Setup

```powershell
# Windows
py -3.11 -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python scripts/download_models.py
```

```bash
# Linux / macOS
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python scripts/download_models.py
```

`download_models.py` fetches the old model's weights (`.pth`) and network file, plus the new model (`best_model_quantized.onnx`). The InsightFace `buffalo_l` pack downloads itself to `~/.insightface/models` on first run.

Always run the scripts from the project root folder.

## Usage

### 1. Prepare enrollment photos

Create the folders yourself (they are not in the repo) and put 4 clear photos of each person in their own folder:

```
data/enroll/alice/1.jpg ... 4.jpg
data/enroll/bob/1.jpg   ... 4.jpg
data/enroll/carol/1.jpg ... 4.jpg
```

Use real photos of the person (not photos of a screen), with one large, frontal or slightly turned face per photo.

### 2. Enroll

```powershell
python enroll.py
```

For each person, enter the name and the folder path. Press Enter on a blank name to finish. Embeddings are stored in `db/embeddings.json`. Enrolling the same name again replaces that person's entries.

To capture the samples from the webcam instead:

```powershell
python enroll.py --webcam --cam 1
```

SPACE captures a frame (4 per person). `q`, `ESC` or closing the window cancels, and nothing is saved for that person.

### 3. Test on images

Put test photos in `data/test/`: new photos of enrolled people, photos of unknown people, and spoof photos (a phone screen or print showing a face). Then run with the model you want:

```powershell
python test_images.py data/test --model old
python test_images.py data/test --model new
```

The output table shows `live`, `live_score`, `identity` and `sim` for every detected face. Annotated images are saved in `outputs/old/` or `outputs/new/`.

### 4. Live webcam demo

```powershell
python demo_webcam.py --model old --cam 1
python demo_webcam.py --model new --cam 1
```

If `--model` is omitted, the demo asks which model to use. `--cam` is the camera index. If the window is black, try another index (virtual cameras such as Iriun or OBS often take index 0).

Keys: `q` or `ESC` quit (closing the window also works), `s` saves a screenshot to `outputs/`.

| Box colour | Meaning |
|---|---|
| Green | Live and recognized |
| Yellow | Live but unknown |
| Red | Spoof (identity not computed) |

### 5. Compare both models on the same images

```powershell
python check_antispoof.py data/spoof_phone
```

Prints P(real) from the old and new models side by side for every image in the folder.

### 6. See what the models rely on

```powershell
python explain_antispoof.py data/spoof_phone
python explain_antispoof.py data/enroll/alice
```

For each image, saves `outputs/explain/<name>.jpg` with, left to right: an occlusion-sensitivity map for the old model, the same for the new model, and the FFT of the face crop. Red regions are the ones where hiding the patch lowers P(real), meaning the model relies on them. Comparing a real face with a screen replay shows which cues each model uses and where it can be fooled.

## Configuration

Edit `config.py`:

| Setting | Default | Meaning |
|---|---|---|
| `DEFAULT_SPOOF_MODEL` | `"old"` | Model used when `--model` is not given |
| `LIVE_THRESHOLD` | `{"old": 0.50, "new": 0.50}` | Minimum P(real) to count as live, per model |
| `MATCH_THRESHOLD` | 0.40 | Minimum cosine similarity to accept an identity |
| `NEW_PAD` | 1.5 | Crop size for the new model (times the face box) |
| `NEW_REAL_INDEX` | 0 | Output index that means "real" in the new model |
| `NEW_SCALE_255` | True | Divide pixels by 255 before the new model |
| `DET_SIZE` | (640, 640) | Detector input size |
| `CAMERA_INDEX` | 1 | Default camera for the webcam scripts |

Tune the thresholds on your own data.

## Spoof testing protocol

For each attack, record the condition, `live_score` and result (screenshot with `s`), and repeat for both models:

| Variable | Conditions to try |
|---|---|
| Attack type | phone screen, monitor, printed photo, cut-out, video replay, paper or 3D mask |
| Media quality | high resolution, low resolution, blurred, compressed |
| Lighting | dim, bright, backlit, screen glare |
| Geometry | near, far, angled screen, head pose |
| Camera | different webcams or phones |
| Appearance | glasses, makeup, face mask, skin tone |

A spoof marked live is a false accept (counts toward APCER). A real face marked spoof is a false reject (counts toward BPCER).

## Observations so far

- Both models accepted at least one phone-screen replay as live in informal tests. The attack conditions and scores are still being documented.
- A real side-pose, backlit, low-resolution face was rejected as spoof by the new model (P(real) = 0.364).

These come from a small set of informal tests and are not a general ranking of the models.

## Privacy

Face photos and embeddings are biometric data. They are excluded from this repo through `.gitignore`. Only use photos of people who have given consent.
