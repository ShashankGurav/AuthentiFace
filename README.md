# AuthentiFace

Face recognition with anti-spoofing (presentation attack detection).

- **Recognition:** InsightFace `buffalo_l`. SCRFD detects the face and the ArcFace model (`w600k_r50`) produces a 512-d embedding.
- **Anti-spoofing:** MiniFASNet (V2 + V1SE ensemble) from [Silent-Face-Anti-Spoofing](https://github.com/minivision-ai/Silent-Face-Anti-Spoofing).
- **Matching:** N:1. One probe embedding is compared against all enrolled embeddings with a single cosine-similarity matrix product.
- **Pipeline order:** detect face, then spoof check, then recognition (only if live). Spoofed faces never reach identity matching.

The project aims to demonstrate the system and to find the conditions under which MiniFASNet fails.

## Project structure

```
authentiface/
├── config.py              # thresholds, paths, model list
├── enroll.py              # enroll people into the JSON database
├── test_images.py         # run the pipeline on images or folders
├── demo_webcam.py         # live webcam demo
├── scripts/
│   └── download_models.py # downloads MiniFASNet weights + architecture
├── src/
│   ├── face_engine.py     # InsightFace detection + ArcFace embedding
│   ├── antispoof.py       # MiniFASNet inference (2 models, fused)
│   ├── minifasnet_arch.py # network definition (downloaded)
│   ├── database.py        # JSON embedding store
│   ├── matcher.py         # N:1 cosine matching
│   ├── pipeline.py        # detect -> spoof check -> recognize
│   └── viz.py             # box and label drawing
├── models/antispoof/      # .pth weights (not in repo)
├── db/embeddings.json     # generated by enroll.py (not in repo)
├── data/enroll/<person>/  # enrollment photos (not in repo)
├── data/test/             # test and spoof photos (not in repo)
└── outputs/               # annotated results (not in repo)
```

## Requirements

- Python 3.11.9
- Windows, Linux or macOS. CPU is enough; no GPU needed.
- On Windows, `insightface` may need the Microsoft C++ Build Tools ("Desktop development with C++" workload).
- Internet access on first run (about 280 MB for InsightFace models).

## Setup

```powershell
# Windows
py -3.11 -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python scripts/download_models.py
```

```bash
# Linux / macOS
python3.11 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python scripts/download_models.py
```

The InsightFace `buffalo_l` pack downloads itself to `~/.insightface/models` on first run.

Always run the scripts from the project root folder.

## Usage

### 1. Prepare enrollment photos

Put 4 clear photos of each person in their own folder:

```
data/enroll/alice/1.jpg ... 4.jpg
data/enroll/bob/1.jpg   ... 4.jpg
data/enroll/carol/1.jpg ... 4.jpg
```

Use real photos of the person (not photos of a screen). Use one large, frontal or slightly turned face per photo. Avoid heavy side profiles.

### 2. Enroll

```powershell
python enroll.py
```

For each person, enter the name and the folder path. Press Enter on a blank name to finish. Embeddings are stored in `db/embeddings.json`. Enrolling the same name again replaces that person's entries.

To capture the samples from the webcam instead:

```powershell
python enroll.py --webcam
```

(SPACE captures a frame, 4 per person.)

### 3. Test on images

Put test photos in `data/test/`: new photos of enrolled people, photos of unknown people, and spoof photos (a phone screen or print showing a face). Then run:

```powershell
python test_images.py data/test
```

The output table shows `live`, `live_score`, `identity` and `sim` for every detected face. Annotated images are saved in `outputs/`.

### 4. Live webcam demo

```powershell
python demo_webcam.py 1
```

The argument is the camera index. If the window is black, try another index. Virtual cameras such as Iriun or OBS often take index 0.

Keys: `q` quit, `s` save a screenshot to `outputs/`.

Box colours:

| Colour | Meaning |
|---|---|
| Green | Live and recognized |
| Yellow | Live but unknown |
| Red | Spoof (identity not computed) |

## Configuration

Edit `config.py`:

| Setting | Default | Meaning |
|---|---|---|
| `MATCH_THRESHOLD` | 0.40 | Minimum cosine similarity to accept an identity |
| `LIVE_THRESHOLD` | 0.50 | Minimum "real" probability to count as live |
| `DET_SIZE` | (640, 640) | Detector input size |

Tune the thresholds on your own data.

## Spoof testing protocol

For each attack, record the condition, `live_score` and result (screenshot with `s`):

| Variable | Conditions to try |
|---|---|
| Attack type | phone screen, monitor, printed photo, cut-out, video replay, paper or 3D mask |
| Media quality | high resolution, low resolution, blurred, compressed |
| Lighting | dim, bright, backlit, screen glare |
| Geometry | near, far, angled screen, head pose |
| Camera | different webcams or phones |
| Appearance | glasses, makeup, face mask, skin tone |

A spoof marked live is a false accept (counts toward APCER). A real face marked spoof is a false reject (counts toward BPCER).

## Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError: src` or `config` | Run from the project root |
| Black webcam window | Try another camera index; add `cv2.CAP_DSHOW` on Windows |
| `[skip] no face in X.jpg` | Use a larger, clearer, more frontal photo |
| Import error in `antispoof.py` | Check class names in `src/minifasnet_arch.py` |
| `insightface` install fails (Windows) | Install Microsoft C++ Build Tools, then retry |
| `FutureWarning: tform.estimate` | Harmless |

## Privacy

Face photos and embeddings are biometric data. They are excluded from this repo through `.gitignore`. Only use photos of people who have given consent.
